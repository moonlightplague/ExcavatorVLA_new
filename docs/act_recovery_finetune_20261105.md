# ACT成功纠错数据微调（2026-11-05）

用户审核视频后批准开始两组各400步的对照。实验目录：`outputs/experiments/act_recovery_finetune_20261105_01/`；入口：`scripts/run_act_recovery_finetune.py`。具体协议、采样身份与源码在第一次优化前冻结。

本轮已结束，纠错微调未通过验收。三组各完成同样三个开发场景：同期基准1/3成功、普通续训2/3成功、纠错微调0/3成功；纠错组在三场均未入车。634个纠错训练状态的前三步动作MAE由0.174652降至0.035787 rad/s（下降约79.5%），但原验证的approach_contact、loaded_transit两阶段超过预设保护条件。训练拟合改善没有转化为这三个场景的自主任务成功，不能据此推广为纠错方法普遍无效，也不能把普通续训2/3当作新的整体成功率。

原20场失败案例在同期基准复跑中成功，粒子/接触演化与旧轨迹没有稳定复现；组间profile、目标上下文及初始关节姿态均已核对。只报告同期对照，不把旧失败到新成功直接归因为模型更新。新seed3100000–3100003未启动，未追加步数或调整比例，未替换27.5%基准。后续应先核对新策略实际失败状态与纠错数据覆盖，并检查原阶段退化，当前未启动下一轮。

完整数值及九场结果见实验目录`REPORT.md`。两组重载检查、原处理器字节一致性、5812/5688个不同实际抽样观测的parquet对齐均通过；纠错组实际5760个原观测、640个专家观测，有效专家动作监督质量占比7.17%。仅保留各组第400步检查点。

两组从独立保留的PHW40k权重开始，batch16、学习率1e-5、原AdamW参数、BF16训练、相同seed1000，优化器重新初始化。不从零训练，不更改网络、10动作chunk/每3步重规划、原L1/PHW/KL损失或原处理器和归一化。control从原训练episode均匀有放回抽取6400个观测；recovery保持其中5760个观测及其位置完全一致，另640个位置替换为成功专家后缀，三个纠错episode各抽取214/213/213个观测。10%是当前观测占比，未来chunk有效PHW监督质量另行记录，不能等同为10%损失权重。

新数据为`data/act_recovery_20261105_v1/`，仅634帧通过物理执行和完整任务成功验证的专家后缀可抽样。747帧原模型前缀不抽样，失败或中止尝试不纳入。相同episode/frame在两个数据集中的身份按source隔离。每次实际训练读到的动作、状态、权重和padding与各自parquet逐项核对，并核对实际采样顺序与冻结清单。处理器保留原字节，只导出原ACT推理结构；每组只保留预算终点第400步权重。

专家采集允许额外恢复预算：第1/9/20场包含原模型回放前缀的完整长度分别379/434/568步；第20场超过原评估500步。因此专家成功只能证明该动作序列满足物理任务条件，不代表ACT在原时限内成功。本轮三模型评估仍固定500步，不延长时限来迁就专家演示。

原验证/测试episode不进入训练。三条纠错轨迹来自原40场开发案例1、9、20，这三个场景微调后属于训练场景修复检查，不能作为独立泛化成绩；原27.5%历史分数不事后重算。

离线核对原训练/验证诊断观测以及全部634个纠错训练观测的零潜变量推理动作。纠错数据上的误差仅说明训练拟合。原验证保护条件预先固定为每个阶段的前三步动作MAE不超过`max(1.10 × 基准, 基准 + 0.005 rad/s)`。

微调完成后，基准、control、recovery各自在1、9、20三个固定原几何场景从起点自主运行，一共9场。三组均沿用原−130°斗杆优先、opening_pose释放、互锁关闭的保料层，原PhysX/资产/评分、10Hz、500步上限，每场全新模拟器，无专家接管、无动作回放。场景profile、目标上下文和初始关节姿态在组间核对；物理粒子演化不宣称逐粒子确定。

只有原验证保护条件通过，且recovery在三个开发场景上的完整任务成功数严格高于baseline和control两组，才运行预先冻结的新seed3100000–3100003，三组共12场同期对照。四个新场景仅是小规模泛化试验，不作为最终成功率。否则按协议停止，不追加步数或调整混合比例，不替换27.5%基准。

当前运行进度以实验目录的`status.json`、`train/*/status.json`为准；最终记录见`training_results.json`、`offline_metrics.json`、`closed_loop_results.json`、`advance_decision.json`、`REPORT.md`。

训练中发现无损纠错视频随机寻帧成为主要耗时，新增独立的评估读取缓存，见`evaluation_io_amendment.json`和`scripts/act_recovery_video_cache.py`。缓存与原解码器27帧探针逐像素完全一致，并与全部4143帧原始相机采集逐像素核对通过。运行中的训练worker已加载原解码器，未替换；仅后续离线评估通过单独冻结的LeRobot源码副本缓存纠错视频RGB帧。动作、状态、时序、原归一化和模型计算不变；原数据视频仍由原解码路径处理，闭环仿真继续使用保留基准的原运行时。评估副本和缓存源码另行逐文件记录哈希，原基准目录未改。
