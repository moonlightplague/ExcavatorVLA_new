# 交接等待版：全新随机40场验证

用户同意对`secure_align＋unload_pose_hold＋unload_handoff_wait`做全新随机40场验证，不设对照，直接报告本批成功率。目录为`outputs/experiments/act_handoff_wait_random40_20261106_01/`。

新增等待精确复制`act_unload_wait_20261106_01`已通过小规模开发验证的冻结控制器和组件，不使用后来修改的工作区版本。只在已验证的对准交接点且原卸料保持尚未启动时固定父关节姿态，最多等待ACT开斗20步；原保持开始后交回原逻辑，原50步保持预算保留。铲斗继续由ACT和原保料层控制。全过程固定姿态的第一版候选不进入本测试。

该来源实验是已查看场景的开发配对：5个有效配对，原任务完成数2→4；问题组1/3→3/3。第9场未到达配对状态，第30场只剩12步卸料，两版均失败。这些是选定候选的开发依据，不能作为新随机场景的预期成功率或独立提升证明。

运行前固定seed为4200000–4200039，每场使用原随机场景采样器生成新的料堆/卡车位置，初姿仍为原数据episode 0。沿用PHW40k模型、处理器、归一化、原始PhysX/资产、逐物理步渲染、10Hz、每3步重规划、500步上限，每场全新模拟器。成功仍要求100粒原料堆粒子入车且铲斗角≥−0.8rad连续三观测。没有额外评分后观察，不恢复旧快照、不回放动作、不使用专家前缀。

分母固定40，任务失败和未触发等待都保留，不按结果更换seed、追加重试或改变参数。不足40场或出现基础设施错误不发布最终有效成功率。没有运行旧版本对照，因此不能据此把与旧57.5%批次的差值归因为新增等待。

入口`run_act_combined_random.py`新增显式`--handoff-wait-source`，默认组合策略仍保留。准备阶段校验来源实验冻结文件和模型、保料/恢复/几何代码及原版父类关系，复制控制器和组件，模拟器仍为没有快照扩展的原始归档版本。原生依赖清单补充新组件和恢复模块，使评估身份覆盖这些文件；评分代码不改。4项运行器检查覆盖随机场景限制、完整分母、等待/恢复计数分离及新增等待完整记录/20步约束。

每场保存完整视频、动作、相机哈希、物料计数和物理时序。辅助指标为入车粒子数、末态留料数、已验证对位交接步、卸料保持与交接等待的触发/步数、等待超时次数，以及episode结束时是否仍在等待。对位步只记录验证完成的`secure_align`交接，原动作编号从0开始；自然到车没有该交接时留空，不错误视为没有到达卡车。等待不计为脱困动作步数。

启动前核对见`preflight_audit.json`；过程见`status.json`；逐场结果和最终成功率见`REPORT.md`和`results.json`。原生汇总器对纯模型的`official_result_valid`原语义保留，本轮明确标注为混合策略评估，另核对其原始成功计数。原57.5%批次和27.5%历史基准均保留，不在本轮运行中替换。正式研究证据作为用户要求的交付保留，临时测试数据和缓存按仓库规范清理。

## 完成结果

40场全部完成，**22场成功、18场失败，成功率55%**，基础设施错误0场。完成时间为2026-11-06 16:50（北京时间）。模型、处理器和冻结输入均未改变，没有替换失败seed、增加步数或运行对照。

25场触发脱困，25场触发卸料保持；新增交接等待触发7场，共9步，其中6场成功、1场失败，0次等待超时，没有场景在等待中到达episode终点。触发子集的6次成功不能解释为新增逻辑独立挽救了6场。

本批55%与旧批57.5%使用不同随机场景，且没有对照，不能把2.5个百分点的差值归因为交接等待。当前没有足够证据认为新增等待提高整体成功率，因此不据此替换默认组合。

18场失败中，15场没有启动卸料保持；11场结束时斗内仍保留至少100粒。这些描述有重叠，表明需要优先复核到车前的对位规划、恢复接管与到位时机。另有6场记录了有限对位规划未解、1场恢复预算耗尽；3场启动保持时斗内均不足100粒。有限规划未解不等于机械不可达，低留料也不证明物理不可能。这些标签描述记录，不作为独立因果归因。

原生及独立审计通过：15,046条动作观测，40份实际几何、40个独立模拟器进程，45个保护输入文件均核对一致；原基准826个文件和旧随机40场419个证据文件再次确认不变。结果见`postflight_audit.json`；失败逐场复核与视频入口见`FAILURES.md`。完整文件哈希保存在`evidence_sha256.json`。两张GPU已释放。
