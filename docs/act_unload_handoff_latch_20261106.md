# 卸料交接优化：失败复盘与开斗前等待

用户指出组合策略随机40场仍有未入车情况，要求继续优化。本轮以57.5%版本为对照，不改变ACT权重、物理、资产、成功门槛或原500步时限。

只读复盘入口：`scripts/audit_act_unload_handoff.py`；审计目录：`outputs/analysis/act_unload_handoff_20261106_01/`。40场中的17场失败分为：4场已经启动保持但启动时斗内不足100粒、4场完成对位但未启动保持、3场有限对位规划未解、1场接管预算用完、1场恢复过程空斗、4场未完成对位。分类见审计`audit.json`，不把有限规划未解等同于机械不可达。

第15/16/21/34场启动保持前斗内分别70/41/68/62粒，保持后都已卸空，未出现5秒预算耗尽。继续加长同样的保持不能据此解释为解决了问题。第10/13/28场交接时仍有155/135/138粒，原控制器已经验证对位，但ACT首步铲斗动作约0.030/−0.037/−0.029rad/s，低于0.12rad/s触发阈值；保持未启动，父关节随后移动，出料点离开车斗。第18场也属于这种交接空档，但当时只有29粒，作为载料不足案例单独保留。

候选实现：`scripts/act_unload_pose_latch.py`。保持入口增加“已完成并验证的secure_align交接”，不依赖ACT同时给出较强开斗指令；原有自然到车开斗入口保留。交接时保存一次回转/大臂/斗杆位置，以这个固定位置修正积分目标；原版逐帧用当前实测位置作目标，会允许漂移累积。最多等待ACT开斗20步，开斗后最多保持50步，空斗连续三观测释放；等待不到开斗则退出。保持期间铲斗仍由ACT控制，没有增加强制开斗、按评分控制或改动挖掘/运输规划。

第一版6项组件检查通过：交接无开斗意图也能进入等待；固定目标不跟随实测漂移；无交接/无意图不打断ACT；等待/开斗预算独立且有界；连续空斗退出；补丁不修改原恢复器。另有5项既有快照/指标检查通过。在第10/13/28场原始记录上逐步重建控制器，确认候选恰在原交接步启动、当前版不启动，且该步铲斗指令与原版一致，结果见实验`recorded_handoff_checks.json`。

正式开发对照为`outputs/experiments/act_unload_latch_20261106_01/`。问题场景10/13/28和原成功场景9/24/30，各2次全新自主共同前缀。在首次验证对位交接或原保持启动之前保存快照，随后配对当前版和候选版，每个分支100步或原500步剩余时间。第一轮每场另重复一次当前版，量化快照恢复后的PhysX波动；不更换未到达或失败案例。来源为刚结束的随机40场，这些场景现在属于已查看开发数据。

沿用此前的完整物理量恢复核对、相同首帧/动作队列/RNG、固定斗内粒子ID比例、原完整任务条件和分支结束后的独立3秒观察。PhysX内部接触缓存与渲染历史没有序列化，不宣称完全确定性复现。

推进条件在任何分支运行前固定：至少8组有效配对，其中问题场景至少4组、成功场景至少3组；问题组平均入车比例提高至少10个百分点、完整任务成功数至少多2次；成功对照完成数不下降；平均斗外且车外比例增加不超过2个百分点；同状态重复当前版的入车比例差均不超过5个百分点。未通过则不修改本轮阈值、延长训练或按结果追加案例。

进度和结果见实验`status.json`、`REPORT.md`、`results.json`。本轮不生成新的随机40场总体成功率，不替换57.5%组合及27.5%历史保留基准。正式研究证据保留，单元检查临时数据在上下文结束后清理；输出和缓存沿用既有gitignore。

## 第一版结果：保留证据，不升级

12次自主前缀全部完成，8次到达快照，4次未到达；8个配对中原任务完成5→7次，问题组1/4→3/4，成功组4/4→4/4。固定斗内粒子平均入车比例差为+15.47个百分点，问题组为+38.57个百分点。这些来自已查看场景的配对实验，不是新随机场景的整体成功率。

存在两个不予升级的原因。第9场第二次前缀虽然两版都达到了原任务门槛，固定斗内粒子入车比例却从99.61%降到69.14%，下降30.47个百分点，说明在开斗全过程锁定同一目标会伤害已有成功行为。第13场第一次重复原版的入车比例为70.15%和61.19%，差8.96个百分点，超出事前5个百分点的重复性门槛，因此整轮`advance=false`。没有删除该样本、修改门槛或把它归为候选收益。完整结果见`outputs/experiments/act_unload_latch_20261106_01/UNLOAD_REPORT.md`。

## 第二版：只补开斗前的交接等待

根据第一版的明确物料回退，收窄为`UnloadHandoffWait`：只有`secure_align`已验证完成、有载料、仍处于原放料几何范围且原卸料保持未启动时，锁住该交接姿态最多20步。一旦原保持启动，立即退出并原样传递其动作；原保持代码逐字保留，不改它的触发阈值、目标、计时或退出逻辑。铲斗依然由ACT控制，没有强制开斗。新增4项单元检查确认原保持动作原样通过、等待交还、代码块完整保留，以及等待预算/空斗/恢复接管退出，现共10项组件检查加5项既有快照/指标检查通过。

第二轮是事前固定的小规模确认实验：目录`outputs/experiments/act_unload_wait_20261106_01/`，同样6场10/13/28/9/24/30，每场1次新自主前缀，不按结果追加重试；每个可配对状态都测试原版、等待版和重复原版。仍使用100步分支/500步剩余时间、固定粒子ID、相同恢复检查与独立3秒观察。

运行前固定的推进条件为至少4个配对，其中问题至少2个、成功对照至少2个；问题组平均入车比例提高至少10个百分点、任务成功至少多1次；成功对照任务完成不下降；平均斗外且车外比例增加不超过2个百分点；重复原版差均不超过5个百分点。与第一版分开报告，不把第二版结果用于宣称第一版通过。协议、分析脚本和开斗窗口定义均在首个分支运行前冻结。

独立的记录输入审计`audit_act_unload_wait.py`已逐步重建旧40场全部控制器输出，最大误差为0。第二版在原第10/13/28场的已验证交接点均能启动，原版保持均未启动，且该步铲斗命令不变。23条原成功记录中20条的候选动作逐步完全相同，8/9/33三场会启动新增等待，因此仍需物理验证；这项审计复用记录输入，不能当成候选反事实任务成功率。结果见第二轮`recorded_controller_audit.json`。

第13场同状态的左右视频保存在`outputs/experiments/act_unload_wait_20261106_01/review/scene13_current_vs_wait.mp4`，左侧当前版、右侧等待版；原分支完整视频和逐步记录均保留。`review/provenance.json`记录源视频哈希和拼接方式。

结论：优先保留“开斗前交接等待”这一窄改动；第一版全过程固定目标不升级。后续新随机场景验证应覆盖原成功记录中也会触发等待的8/9/33类交接，并继续关注入车物料比例。其余失败中，已经保持且卸空但到位时物料不足的4场，需要前移到闭斗/抬升/运输留料优化；规划未解、漏接管和第30场这类过晚到位也不会由增加卸料保持时长解决。本轮未更改默认控制器、ACT权重或原成功门槛；57.5%组合和27.5%历史基准继续保留。

独立核对入口为`scripts/audit_act_unload_trial.py`。第一轮20次恢复、3547条前缀观测与2000条分支观测核对通过，保持基准826文件和原随机40场419证据文件不变。第二轮最终审计见该轮`postflight_audit.json`；事后审计源文件另存`audit_sources`，与运行前冻结的`analysis_sources`区分。

第二轮最终核对通过：6个计划案例全部保留，15次物理状态恢复、1863条前缀观测与1236条分支观测；最大恢复地标误差4.3422×10⁻⁶米。原任务完成数由逐步记录独立重算一致，固定粒子分类守恒，55个冻结输入文件及预先冻结分析脚本均未改变；基准826文件和原随机40场419证据文件再次逐一核对不变。15项组件/快照/指标单元检查通过，临时字节码已清理，正式研究证据和视频保留。两块GPU均已释放。
