# ACT 释放互锁：GPU 平衡重复复核（2026-11-04 开始，11-05 完成）

为减少互锁基线与候选总在不同 GPU 上运行带来的混杂，使用原 `opening_pose` 几何，在第 8、16、34、38、6 场各对互锁开/关重复两次，并在第二次交换 GPU 分配。共20次新模拟器运行，500步上限；同一场景 seed、参考场景几何、初始姿态、PHW40k和−130°斗杆优先保料约束固定。检查点哈希未变化，运行均完整结束。场景是为诊断挑选的固定案例，不是随机独立样本。

## 结果

| 场景 | 基线完成 | 互锁完成 | 基线入车（两次） | 互锁入车（两次） |
| --- | ---: | ---: | --- | --- |
| 8 | 2/2 | 2/2 | 241, 244 | 282, 253 |
| 16 | 1/2 | 0/2 | 211, 47 | 68, 34 |
| 34 | 1/2 | 0/2 | 50, 166 | 0, 0 |
| 38 | 0/2 | 0/2 | 0, 0 | 0, 0 |
| 6 | 2/2 | 1/2 | 252, 118 | 0, 209 |
| **合计** | **6/10** | **3/10** | **每次入车粒子数** | **每次入车粒子数** |

互锁在第 8 场的两次重复都完成，入车计数也高于各自对照；但第 16、34 场未复现对照中的成功，第 6 场出现一次未起运。第 38 场两版均未起运。这说明互锁效果依赖场景和单次物理轨迹，当前证据不支持全局默认启用，也不能把较高留料解释成优化成功。

因此评估 CLI 的 `--act-carry-release-interlock` 和调试 CLI 的 `--release-interlock` **默认关闭**；需要时可显式打开。`load_point` 仍是默认解除几何，ACT 权重未改。斗外计数包含空中物料，不等同于已经落地的沙。
