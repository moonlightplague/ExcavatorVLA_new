# velocity 8k 的记忆扰动恢复试验（2026-11-21）

用户授权继续以回程强化模型为基础优化。保留原velocity 8k，并保留前一版回程衔接试验作对照。当前仅新增训练目标，部署模型结构及公开输入/输出完全相同。

## 失败证据与待检验假设

在已完成三组对照中的原模型轨迹里，场景50第7轮运料、场景141第2轮运料均到达回转角约-π且继续输出负回转速度，持续至预算结束。该观测证明存在偏离轨迹后的恢复失败，不能证明错误一定由记忆造成。新试验检验：训练中增加隐藏状态误差暴露，是否能改善已有记忆模块依据当前真实观察恢复动作的能力。

## 训练方案

输出目录：`outputs/experiments/act_memory_robustness_20261121_01`。

- 从原velocity 8k初始化；冻结视觉、ACT核心和短历史，只更新已有256维GRU、特征投影及动作残差头。无位置动作头、阶段输入或外部控制器。
- 延续衔接版140/20/40固定划分、160个只读冻结特征缓存、128次预测片段、完整因果前缀重建、回程及实际执行步加权、源模型动作约束、1500步小规模微调。缓存核心、统计及哈希检查保持。
- 每个训练批同时保留干净记忆路径与扰动路径。扰动仅作用于训练片段开始的内部隐藏状态：10%样本清零，20%使用本批其他真实训练父episode的隐藏状态并叠加噪声，70%仅添加RMS比例0.05的高斯噪声。
- 所有图像/物理状态特征、专家动作及动作padding均保持不变，训练标签不作为模型输入。部署时没有记忆扰动、额外重置或任何动作规则。
- 扰动路径训练前16次预测的恢复动作，添加系数0.25的原专家/方向/源动作约束损失及系数0.02的干净动作一致性项。干净分支输出在一致性目标中停止梯度。
- 使用独立随机数生成器采样扰动，保持训练父episode/片段抽样序列与前一衔接版相同。增加了恢复分支监督，故与旧衔接版的比较不能隔离“扰动”与“额外监督量”两者贡献；如有收益，再作匹配监督量的对照。

## 检查、筛选、评估

先运行CPU真实数据检查，不干扰正在GPU1运行的衔接版评估。检查包含扰动形状/数值/原隐藏状态不被修改、完整前缀与片段一致性、两次真实梯度更新、仅记忆参数变化及标准RGB推理重载；临时权重删除，仅保留检查证明。

GPU0先训练，无需等待正在GPU1上的衔接版闭环结束。验证保持全量及回程首动作误差不超过源模型1.02倍、回程方向错误不超过源模型加1、bridge首动作误差不增加，并新增固定隐藏状态清零/扰动压力检查：扰动后执行动作误差和动作敏感性均不得增加。压力检查只在专家观察上进行，不代表实际闭环恢复。

仅保存最终1500步权重。通过筛选后等待前一衔接版四次HDR复测正常完成，再使用同一私有HDR评估配置，在场景50/112各进行两次2000步开发检查。未通过筛选则停止该分支并记录拒绝，不自动替换原基准。

代码：`scripts/train_act_memory_robustness.py`、`scripts/check_act_memory_robustness.py`。使用已有私有兼容运行环境，不修改旧训练脚本、旧运行时、共享模拟器/评估器或成功标准。

## 首次1500步结果

试训已完成并通过筛选、冻结核心检查、严格权重及原始RGB在线重载。回程首动作误差0.0191428→0.0190002，约下降0.75%，回程主动方向错误维持3个；全量首动作误差0.0455222→0.0454848。固定记忆压力检查中，扰动引起的动作变化0.00128736→0.00106226，约下降17.5%；扰动后专家动作误差0.0543801→0.0541888，约下降0.35%。这些仅是离线专家观察压力检查，尚无闭环恢复改进结论。
